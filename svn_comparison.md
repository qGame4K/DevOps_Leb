# Git vs SVN

1. **Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?**
   В Git ветка — это просто лёгкий указатель (файл на 41 байт) на конкретный коммит; создание ветки не копирует файлы и происходит мгновенно. В SVN ветка технически реализована как полная копия директории проекта в репозитории (`svn copy`), поэтому она занимает место, требует передачи данных на сервер и выполняется заметно дольше.

2. **Можно ли в SVN сделать коммит без интернета? Почему?**
   Нет. SVN — централизованная система: вся история хранится только на одном центральном сервере, а у разработчика локально лежит лишь рабочая копия файлов без полной истории. Коммит — это операция записи в центральный репозиторий, поэтому без сети закоммитить нельзя (можно только редактировать файлы локально).

3. **В каких сценариях SVN до сих пор может быть предпочтительнее Git?**
   - В legacy-проектах (особенно в госсекторе и банках), где вся инфраструктура и процессы уже годами завязаны на SVN, и миграция дороже пользы.
   - При работе с очень большими бинарными файлами без Git LFS — SVN исторически проще справляется с большими бинарниками, так как не хранит полную историю у каждого разработчика.
   - Когда нужен жёсткий централизованный контроль доступа на уровне отдельных папок репозитория (SVN поддерживает это нативнее, чем Git).
